# credbone.com

Personal site / UI component showcase. A Create React App project (React 18 + TypeScript) that lives in `credbone/` and deploys to GitHub Pages at credbone.com.

## Concept
Three parts: **Components** (the CredBone UI framework showcase and design system), **Tools** (small creative web tools such as the avatar maker, color mixer and path builder) and **About/Resume** (portfolio). Everything should feel like one product: a consistent, polished, design-led UI built on the framework itself.

## Project specifics
- **Theme is user-customizable:** primary/secondary colors are generated at runtime (`styles/skin.ts`, `ThemeProvider`), so any color can change. Always use tokens.
- **Font size is user-adjustable:** `FontSizeProvider` rewrites `--text`. Use `data-text-size` values (`medium-small`, `medium`, `large`, `x-large`…) or `var(--text)`-relative sizes, never fixed px font sizes.
- **New tool:** add it to `pages/tools/toolData.ts` (title, thumb from `toolThumbs.tsx`, short description, url, `new:"true"`) plus its route.
- **"New" badges:** nav and tools items use `new:"true"`. Set it on new items, and suggest clearing old ones.
- **Feedback messages** go through `useSnackbar().addSnackbar(...)`. Don't use `alert()` or custom toasts.
- **SEO:** a new public route also gets an entry in `public/sitemap.xml`.
- **Don't edit:** `src/buildInfo.json` (generated by `generateBuildInfo.js` at build time and git-ignored), `public/cv.pdf`, `public/CNAME`, `public/404.html` (GitHub Pages SPA redirect).

## Commands (run inside `credbone/`)
- `npm start`: dev server on port 5000
- `npx tsc --noEmit`: type-check (this is how to verify changes)
- `npm run deploy`: builds and publishes to GitHub Pages. Never run this.

## Layout
- `src/components/`: reusable components (button, Modal, tooltip, popover, inputs/, tabstrip/, snackbar/, dashboard/, icons…)
- `src/pages/`: site pages (about, resume, settings, search, tools/)
- `src/template/`: component demo pages
- `src/styles/`: all CSS. `base/` holds globals and theme variables (`project.css`), `controls/` holds per-control styles. `skin.ts` / `paletteUtils.ts` generate the color palette.
- Theming: `ThemeProvider` sets `data-theme` = `light` | `dark` | `auto`, and colors come from CSS variables.

## Markup conventions (the house style)
- **Layout uses custom tags, not divs:** `<group>`, `<text>`, `<icon>`, `<separator>`, `<picture>`, `<view>`, `<badge>`, `<space>` and so on. They're registered in `src/configs/customTags.tsx`. A new tag must be added to that set before it's used.
- **Styling uses `data-*` attributes, not classNames:** `data-gap`, `data-space`, `data-radius`, `data-direction`, `data-align`, `data-wrap`, `data-width`, `data-background`, `data-contain`, `data-opacity`, `data-weight`, `data-text-size`… They're defined in `src/styles/base/control.css`. Check there for an existing attribute or value before writing CSS. Classes (`.button` etc.) are for components only.
- **Spacing scale:** gap/space values are 5, 10, 15, 20 and 30 (50 occasionally). Radius values are 5, 10, 15, 20, 30, 40 and `full`. Don't invent in-between values.
- **Colors:** use the theme tokens through attributes such as `data-background="main-background" | "adaptive-gray" | "context" | "text" | "main"` and `data-color`. Never use raw hex.
- **Interactive items:** `data-interactive=""` + `data-cursor="pointer"`, and wrap in `<Ripple>` where other items do. Use `<Tooltip content=…>` for hints.
- **Icons:** `lucide-react` at `size={20}`, wrapped in `<icon>`. Custom brand icons and illustrations come from `components/icon/credIcons.tsx` and `svgRes.tsx`.
- **Responsive:** `data-adaptive="desktop" | "mobile"` (or `desktop-500`, `mobile-600`…) to show or hide. The main CSS breakpoints are 800, 600 and 500px.
- **Motion:** entrance animation is `data-animation-name="appear-bottom"` (plus `appear-top`, `zoom-in`) with `data-fill-mode` / `data-animation-duration`.
- **Adding a component demo page:** it lives in `src/template/`. Also add it to `pages/navigation/subroutesData.ts` (nav) and `pages/search/routesData.ts` (search, with title, description and tags).

## Adding anything new
Everything new must use the conventions above and fit the existing structure without conflicts:
- **Search before creating.** Before adding a tag, attribute value, CSS variable, class or component, grep for it. Extend what exists instead of making a parallel version.
- **New CSS file:** put it in `src/styles/controls/` (one file per control), start it with the header comment `/* CredBone UI Framefork Component / Layout / Version 3.0.0 */` and import it in `src/styles/controls/index.ts`. Don't import CSS from components.
- **New `data-*` utility value:** add it next to its siblings in `control.css`, following the existing naming pattern (e.g. a new `data-gap` value goes with the other gaps).
- **New CSS variables:** declare them in that control's `:root` block with a control prefix (`--tooltip-…`, `--button-…`) so they can't clash with global tokens.
- **Scope selectors:** `group.my-control`, `.my-control text` and so on. Never restyle bare global tags (`text`, `group`, `icon`) or override another control's rules from a new file.
- **No `!important`.** Don't fight the cascade; adjust the right rule instead.
- **New custom tag:** add it once to `customTags.tsx` (check it isn't already there) and to the JSX `IntrinsicElements` list in the same file.
- **New component:** put it in `src/components/` (or a subfolder for a family), as a typed `React.FC` with a props interface, and use `classnames` for conditional classes, like `button.tsx`.
- **New page or route:** register it in `App.tsx`, nav (`subroutesData.ts`) and search (`routesData.ts`), so it's never orphaned.
- If a new piece doesn't fit any existing pattern, stop and propose where it should live before writing it.

## Working rules
- **Git:** never commit, push or deploy. Leave changes uncommitted so I can review them.
- **Styling:** reuse existing CSS classes from `src/styles` first. Add new CSS only when nothing fits, and put it in the matching file under `src/styles`, not inline.
- **Components:** reuse existing components from `src/components`. Create a new component only when it's genuinely needed, and say so.
- **Mobile + dark mode:** every UI change must work at phone widths and in light, dark and auto themes. Use theme CSS variables, never hard-coded colors.
- **Suggest, don't sprawl:** if you see improvements beyond the request, suggest them rather than making them.
- **Verify:** type-check with `npx tsc --noEmit`. No browser check needed unless I ask.
